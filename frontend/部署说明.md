# Paper Choose 前端与部署说明

## 分工

`src/pages/Workbench.jsx` 管理四步流程；`src/components/pc/` 保留 Base44 页面设计。
`src/lib/localBackend.js` 请求本机 Python 服务；`src/lib/batches.js` 将长原稿切成不超过单次翻译限制的批次。
`base44/functions/checkTranslation/entry.ts` 为云端 AI 核对函数，仅返回建议。定位、保护约束、作者选择与导出由根目录 Python 执行器校验。

## 本机版

普通使用者直接启动根目录 start_windows.cmd。
修改源码后，在此目录运行 `npm ci`、`npm run build:local`，再运行 `python ../scripts/install_webapp.py`。Python 本地服务同源托管页面，避免额外开放跨域；原页面仍在 /classic。

`.env.pclocal` 含作者提供的非秘密应用 ID，用于选择 checkTranslation 服务。自建服务时改成自己的应用 ID，并部署对应云端函数。不要把 API 密钥、服务角色密钥写进前端或 VITE_ 变量。

仅需调试前端时，构建后通过 Python 服务查看；不要把 http://localhost:5173 填入只接受 HTTPS 的 --allow-origin 参数。

## 可选云端网页

需要连接已经发布的 HTTPS 网页时，运行根目录 start_cloud_windows.cmd，填写网页的 HTTPS 来源（协议与域名，不带路径）。本机仅允许该来源访问，仍校验会话令牌。浏览器可能另行限制访问本机；这条跨容器、跨域路径尚未在本轮真实 Windows 浏览器验收。

## Base44 云端

保留原 SDK 和 `checkTranslation` 函数。Base44 云端函数依赖其平台集成，不能仅靠 GitHub Pages 执行。请在自己的 Base44 项目导入函数并按平台发布流程部署。
本轮只更新 GitHub 源码和本地构建产物，不修改 Base44 账户、权限、计费或部署。仓库未核实自动同步，不能把 GitHub commit 当成云端部署成功。

## 限制与数据

- Argos 每次最多 5000 字符；页面自动分批，保留首尾分隔、顺序和当前页面内的失败进度。
- 输入变化、手动编辑译文或离开翻译面板后，旧任务不能覆盖当前稿件。刷新/关闭后不能恢复进度。
- 核对独立限制：原稿和译文各 15000 字符，前端 `CHECK_MAX` 与函数 `MAX` 应一致；超出拒绝，不截断。
- 云端核对只在双项同意并点击开始后发送稿件与术语。前端不自动保存论文；云端服务留存由提供方政策决定。
- 本地构建不启用 Base44 编辑器遥测注入；托管构建沿用平台插件。字体来自原设计的 Google Fonts，离线时使用后备字体。
