# 原界面说明（保留入口 /classic）

以下操作仅用于原界面。新网页请阅读根目录 README.md。

# Paper Choose：机翻后，只改你选中的地方

**已有论文 → 机翻 → AI 一次核对 → 你选择修改 → 下载新稿。**

你已经有一份稿件，希望翻译后保留原意、专业术语和数字。Paper Choose 把原稿与机翻稿放在一起，让你使用的 AI 只提出必要的小范围修改；你选中哪些，程序就执行哪些。表达不同但意思相同，不为“更漂亮”而改写。

支持 **中文→英文、英文→中文**。以作者提供的原稿为依据，不强制先英译中、确认中文、再翻回英文。已有英文且最终仍要英文时，不需要为使用本工具而翻译一圈。

## 你实际需要做什么？

1. **放入原稿，选翻译方向。** 已有机翻稿直接粘贴，没有就使用本地 Argos 翻译。
2. **选择保护方式。** 默认让 AI 自动识别；也可手动添加，或手动填写一部分、AI 补充。可直接跳过手动输入。
3. **一次核对。** AI 同时识别重要术语、检查翻译偏移，只列必要修改；不先让你审核一张长术语表。
4. **选择修改。** 查看原句、依据和最小改法，选中认可的建议。
5. **检查、下载。** 原稿与机翻稿保留，另存新稿和实际修改记录。

例如原稿写“可能改善”，译文变成“一定改善”，就提出修正。译文只是换了一种同义说法，就保留。

### 术语与保护内容怎么选？

| 方式 | 适合怎样使用 |
|---|---|
| 让 AI 自动识别 | 不想先填表；让助手在核对时识别术语、数字、否定、条件和主张强度。 |
| 我手动填写 | 你指定术语和原意要求，助手不额外扩充术语表，但仍检查完整语义。 |
| 我填写一部分，AI 补充 | 手动要求优先，其余交给助手识别。 |

“译文必须保留的准确写法”每行一项，填写本次译文中必须出现的模型名、缩写或名称。其他要求放在说明框，例如“不得将相关关系改成因果关系”。程序会阻止所选修改减少已存在的指定写法，并提示最终仍缺少的写法；这种字面检查不能证明术语位置或语义正确。

如果当前原稿是你修订过的中文，可以展开“另附最初的英文原稿作参考”，粘贴原始英文供追溯。当前原稿决定意思，旧英文不能把你的明确修订改回去。

**AI 自动识别不是自动批准修改。** 保护内容识别与语义判断由你选择的助手完成，所有修改仍等待你选择。

## 让你正在使用的 AI 助手跑流程

把项目和允许处理的原稿交给具备文件、命令权限的助手，例如适配环境中的 Codex、Cursor、Claude Code 或 Grok Bot。可以发送：

> 读取 SKILL.md 和 docs/AGENT_WORKFLOW.md，使用 Paper Choose 处理这份稿件。翻译方向是【中→英／英→中】。保护方式为【AI自动识别／手动／手动＋AI】，我的补充要求是【可留空】。保存原稿，调用本地机翻，在同一轮识别保护内容并核对译文。只列最小修改，等我选择后再执行，不强制往返翻译。

助手负责文件搬运与调用，你负责选择。不同客户端是否能调用，取决于其文件、命令和本地模型权限；这些客户端尚未逐一验收。

**自己使用网页时，仍需把核对请求交给助手，再导回建议。** 网页没有自动云端 AI 后端，选“AI自动识别”不会自动上传稿件，也不代表已经运行了 AI。

## 第一步：把工具下载到电脑

仓库就是这个项目在 GitHub 上存放文件的地方。

1. 在仓库页面上方点击 **Code（代码）** 标签。
2. 在文件列表右上方，点击绿色的 **Code** 按钮。
3. 在展开的菜单中点击 **Download ZIP（下载 ZIP）**。
4. 下载完成后，在电脑的“下载”文件夹里找到 ZIP 压缩包。
5. 右键点击压缩包，选择 **全部提取**。
6. 在弹出的窗口中点击 **提取**。
7. 打开提取出来的文件夹。
8. 找到 `start_windows.cmd`。

如果电脑隐藏了文件扩展名，这个文件可能显示为 `start_windows`。它的类型是“Windows 命令脚本”。

**不要在压缩包里面直接启动。** 请先完成“全部提取”。

**完成检查：** `start_windows.cmd` 旁边应当有 `paperchoose`、`scripts`、`examples` 等文件夹。后文把这个位置称为“项目文件夹”。请保留目录结构，否则程序可能无法启动。

## 第二步：准备 Python（只需做一次）

基础工作台支持 Python 3.10 或更新版本。本候选版的可选翻译依赖限定 Python 3.10–3.12，首次安装建议使用 3.12。

不确定是否已安装时，在终端输入 `py --version`；找不到命令再试 `python --version`。已有符合要求的版本就不用重复安装。

如果没有安装，或者不确定：

1. 打开 [Python 官方 Windows 安装管理器下载页](https://www.python.org/downloads/release/pymanager-264/)。
2. 在页面的 **Files → Windows** 区域，点击 **Download Installer (MSIX)**。下载的是安装管理器，后面还要用它安装 Python 3.12。
3. 打开下载的 `.msix` 文件，按安装窗口的提示完成安装。
4. 在 Windows 开始菜单中搜索并打开 **终端**。终端是输入命令的窗口。
5. 在终端中输入下面的命令并按回车。这条命令会安装 Python 3.12。

```text
pymanager install 3.12
```

6. 安装完成后，在终端中输入下面的命令并按回车。

```text
py -3.12 --version
```

**完成检查：** 终端显示 `Python 3.12.x`。其中的 `x` 表示版本末尾的数字，不需要输入字母 `x`。

如果第一条命令提示“找不到命令”，先关闭终端再重新打开。仍然不行时，参考 [Python 官方 Windows 安装说明](https://docs.python.org/3/using/windows.html)。已经使用其他方式装好 Python 的人，不必重复安装。

只使用原有核对与择项修改功能，不需要额外依赖。若要在页面里直接翻译，请再完成下面的安装。

### 安装本地翻译（可选，只需一次）

1. 在解压后的项目文件夹里双击 `setup_local_translation.cmd`。
2. 窗口会说明需要联网下载依赖和中英模型。愿意安装时按 **Y**，不安装按 **N**。安装程序不读取稿件。
3. 等待窗口显示 `Done`。下载量较大，需要数百 MB 以上空间；速度取决于网络。
4. 关闭原来的工具启动窗口，再按第三步重新打开工具。
5. 页面应显示翻译模型已安装，并可以按所选方向翻译原稿。每次最多处理 5,000 个字符，长稿按章节处理。

若安装失败，保留窗口中的错误信息。原有手动导入译文的功能仍可使用。依赖和模型放在项目里的 `.paperchoose-venv`、`.translation-data` 文件夹中，不需要上传到 GitHub。

已经熟悉命令行的用户，可在项目目录建立虚拟环境后安装 CPU 版 PyTorch、`requirements-translation.txt`，再运行 `python -m paperchoose.translation --download-models`。具体命令见 `docs/LOCAL_TRANSLATION.md`。

## 第三步：打开工具

1. 打开项目文件夹。
2. 双击 **`start_windows.cmd`**。
3. 保持启动时出现的终端窗口打开。
4. 如果浏览器没有自动打开，把下面的地址输入浏览器地址栏并按回车。

```text
http://127.0.0.1:8765/classic
```

这个地址指向你自己的电脑。只有工具启动后才能打开，发给别人也不会打开你的页面。

**完成检查：** 页面显示“本地工具已就绪”。如果页面无法连接，请查看下文“打不开时，先检查这几件事”。

**不要直接双击项目里的 `index.html`。** 页面需要配合刚才启动的程序才能工作。

## 第四步：先试一次合成示例

点 **试用合成示例**，页面会装入专门编写的中英文和预制建议。这不是实际论文，也没有在后台调用 AI。

只勾选 **P1-01**，点 **预览所选修改**：`always improves` 应变成 `may improve`，其余建议涉及的文字保持原样。再点 **全部不采用**，新稿应与机翻稿完全一致。

## 第五步：处理自己的稿件

1. 选择 **翻译方向**，放入左侧原稿。右侧放对应的机翻稿。
2. 按需选择 **术语与保护内容**。手动内容放在展开区；在自动模式下填写，会自动切换为“手动＋AI补充”。
3. 没有译文时，点 **按所选方向翻译原稿**，再点 **放入待核对译文**。此按钮只把机翻稿放进右侧，不是确认译文准确，也不会覆盖左侧原稿。
4. 点 **准备给 AI 的核对材料**。将下载包中的 `AUDIT_PROMPT.md`、`request.json` 和项目的 `SKILL.md` 交给允许处理材料的助手。若需要，再提供 `references` 中相关规则。
5. 请助手“按请求一次完成保护内容识别与翻译核对，返回 audit.json，不直接改稿”。
6. 展开 **交给助手与导回结果**，点击 **导入助手返回的建议**，选择文件，然后 **校验并展示修改项**。
7. 勾选建议，点击 **预览所选修改**，看过差异后 **确认并下载结果**。

修改原稿、机翻稿、方向、保护方式、说明或参考原文后，旧建议会失效，需要重新核对。新流程使用 v2 核对格式，不能直接导入旧的 v1 JSON；旧命令行入口仍保留。

当前支持粘贴与 UTF-8 TXT。Word/PDF 需先复制正文，不能保留其排版。每份文本不超过200KB；本地翻译每次最多5,000字符，长稿按章节处理，不会自动截断。

## 保存进度和结果

- **保存项目**：下载包含原稿、机翻稿、设置和核对清单的文件。下次点击 **恢复项目**。采用项需重新确认，恢复不会自动执行修改。
- **确认并下载结果**：结果包包含 `source.en.txt` 或 `source.zh.txt`（原稿）、`machine.*.txt`（修改前译文）、`revised.*.txt`（新稿）、`changes.diff`（实际差异）、`context.json`、`audit.json` 和 `decisions.json`。
- **下载本次翻译记录**：可另存实际翻译引擎、版本与翻译输入记录。

关闭或刷新前请保存。项目文件和结果包都包含稿件，请自行保存在合适的位置；不要把私人论文上传到公开仓库。

## 打不开或导入失败？

| 情况 | 处理 |
|---|---|
| `No module named paperchoose` | 完整解压后启动；`start_windows.cmd` 必须与 `paperchoose` 文件夹在同一层，不能单独移动。 |
| 页面无法连接 | 保持启动终端打开，通过 `http://127.0.0.1:8765/classic` 进入，不要直接打开 index.html。 |
| 翻译不可用 | 检查模型安装；也可继续导入其他翻译工具的译文。 |
| 原稿、设置或版本不匹配 | 为当前材料重新准备请求，不能改哈希来绕过。 |
| 指定写法保护阻止应用 | 核实建议是否误改名称；如确需变更，先更新作者保护要求并重新核对。 |
| 某项位置不明确或两项重叠 | 让助手补足定位，或选择其中一项；不能强行应用。 |

## 当前实现范围

版本：**2.1.0-dev.2+shortflow.1**，开发候选版。

已加入双向原稿核对、三种保护方式、一次识别与核对的助手协议、项目保存/恢复和独立输出。程序验证版本、引用位置、所选跨度、重叠与选区外不变；不宣称自动证明语义正确。

核对由作者使用的助手或人工完成。BTI/AEC 仍为另行请求的只读诊断；C/D/E 字数管理不在此替换执行器中。没有默认1000词限制，也不为低于字数上限而自动扩写。

使用前请在目标系统检查安装、翻译和导出；短例子的结果不能代表整篇论文的翻译质量。
