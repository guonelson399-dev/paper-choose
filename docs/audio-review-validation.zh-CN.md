# 音频校对扩展：怎样验收
 
状态：验收方案。音频执行器尚未实现；合成文字案例不代表真实音频识别效果。
 
## 两种检查必须分开
 
| 检查 | 依据 | 能证明什么 |
| --- | --- | --- |
| 文档和案例检查 | JSON 可解析、案例编号唯一、预期结果与选择一致、链接存在 | 示例自洽，便于后续开发 |
| 修改执行验收 | 实际音频适配代码调用及输出 | 在覆盖输入中遵守选择、版本与定位约束 |
| 识别效果验收 | 原音频与人工回听参考稿 | 在这些片段中修对、改错和遗漏的情况 |
 
现有翻译执行器的历史测试不代表音频适配通过。本目录 JSON 为设计夹具，不能直接导入现有网页或 translation_audit v2 接口。未提供音频，也没有伪造识别分数或时间戳。
 
## 修改执行器接入后要跑的场景
 
- 全部不选：原始转写字节完全不变（含空格、CRLF、Unicode）。
- 只选 A：只改变指定跨度；B 和其他位置不变。
- 重复词：只改指定那一次，不使用全局替换。
- 音频/文字/术语设置变化：拒绝旧建议，要求重新核对。
- 重叠选项、位置不唯一、保护冲突：明确报错，不部分偷偷执行。
- 未音频核实的候选被作者采用：保留未核实状态，不变成“音频已验证”。
- 无音频、无时间戳：显示段落定位，不造时间。
- 未允许发送音频：不得产生对外音频请求；文字和课件权限分别验证。
 
## 一轮小型真实录音对照
 
选 20–30 个获准处理的短片段，含粤英切换、术语、数字、否定、建议强度、杂音，以及原本识别正确的对照片段。保留前后文；不只挑容易修好的错误。人工回听写参考稿，听不清的地方单独记录，不强行定答案。
 
固定片段与基础模型参数，比较：
 
1. 基础转写；
2. 加相关课件术语提示；
3. 可疑片段重新识别、提出修改建议；
4. 作者实际选择后的最终稿。
 
同时报告建议质量与作者选择后的效果，避免把人工修正功劳全部算给模型。用过的片段可用于调试；后续再留出少量未看过的片段检查效果。
 
记录每段的模型版本、设备、参数、原输出、新输出、人工参考、修改原因、是否采用、回听与修改耗时。至少统计：
 
- 原有错误修对多少；
- 原本正确却改错多少；
- 重要错误遗漏多少（尤其日期、数字、否定）；
- 误报导致多少额外回听；
- 从导入到可用结果总共花多久。
 
没有足够参考答案就不报告准确率。词/字错误率可以辅助，但不能代替关键意思是否保留的检查。
 
## 使用条件

评估需要可读取且获准处理的音频、相关材料，以及人工回听参考。现有案例为合成文字，不能据此声称真实识别准确率或音频修改执行器已通过验收。
