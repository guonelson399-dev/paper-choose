# Paper Choose：英文哪里要改，你来选

**对照中文检查英文翻译，由你选择要修改的地方。**

你已经写好中文，也有一份英文译稿。Paper Choose 帮你按下面的顺序处理：

1. 让你选择的 AI 助手或核对人员，对照中文提出修改建议。
2. 在 Paper Choose 里选择你同意的建议。
3. 查看修改后的英文稿。
4. 下载确认后的结果。

比如说，中文写“**可能提高准确率**”，英文却写成“**一定提高准确率**”。核对的人指出这个区别后，你可以选择把英文改回来。

**程序只执行你选中的修改。** 程序另外生成新稿，保留原文件。

你可以让具备文件和命令执行能力的助手来跑流程，也可以自己操作本地网页。助手模式由当前助手负责核对，调用本地翻译和择项修改程序，不需要为 Paper Choose 另接一个 AI API。单独使用本地网页时，仍需导出核对请求并导回助手的建议。

使用下面的本地网页工具不要求你编写代码。你需要安装 Python，并复制少量命令。

## 从初稿到最终英文，完整流程是什么？

**准备初稿 → 确认中文意思 → 翻译成英文 → 列出问题 → 选择修改 → 保存新稿。**

初稿可以自己写，也可以是在当前课程或项目允许范围内，由 AI 辅助生成的文字。Paper Choose 从已有稿件开始，不负责替你确定论点或核实全部事实。

1. **保存最初的稿件。** AI 生成的初稿也单独留一份，后面的译文和修改稿另存。
2. **确认你想表达的中文意思。** 如果起点是英文，可以先点“英文 → 中文（阅读草稿）”，读懂后检查、修订中文。如果起点就是中文，直接检查中文即可。特别看数字、人名、否定、条件和“可能／一定”。
3. **把确认后的中文翻成英文。** 点“中文 → 英文”，查看译文，再点“我已核对，采用这份译文”。操作就像普通翻译软件：放入文字、选方向、查看结果。这里使用本地 Argos 翻译引擎，并非调用苹果翻译服务。
4. **让 Paper Choose 核对翻译。** 同时提供确认后的中文和刚生成的英文。助手模式中，当前助手自己按技能规则核对并保存编号清单。自己操作网页时，按本页第五步导出请求，再导回助手的结果。
5. **由你选择改哪里。** 只采用你同意的建议，预览后下载。英文没有改变中文意思时，不因为另一种写法更漂亮就改。
6. **保存结果，再放回原文档。** 保留原稿、机翻稿、修改后英文和采用记录，最后检查字数与排版。

**两份文字要一起提供。** 只有机翻英文，Paper Choose 就缺少判断“有没有改意思”的中文依据。中文机翻也可能出错，须经你确认后才能成为本轮依据。已经有确认好的中英文时，可以跳过前面的翻译步骤。

也可以使用你习惯的普通翻译软件，把确认后的中文和原样保存的英文译文复制进来。不要在保存机翻稿之前，再点润色或改写。

### 想让 Codex、Cursor、Claude Code 或 Grok Bot 帮你跑？

把项目文件夹和允许处理的稿件交给助手，再发送：

> 请读取 SKILL.md 和 docs/AGENT_WORKFLOW.md，使用 Paper Choose 完成需要的翻译和核对。先确认中文原意，再给我看编号建议，等我选择后才执行。保留原稿，不自由润色，不另开 API。

有文件和命令执行权限的助手可以调用程序，不用你手动搬运 JSON。具体命令见 [助手操作说明](docs/AGENT_WORKFLOW.md)。你仍负责确认中文意思和选择修改。

这四个是目标使用入口，目前没有逐一完成客户端验收。Grok Bot 需确认具体部署能力；只有聊天权限的入口，仍采用下面的文件交换方式。云端助手与 Windows 本地电脑是不同环境，文件和模型不会自动互通。

### 只想在 AI 对话中使用技能？

这种方式不需要安装 Python。下载项目后，把 `SKILL.md` 和 `references` 文件夹中的规则文件交给支持文件读取的助手，再提供中英文和以下说明：

> 请按 Paper Choose 规则，以我确认的中文为依据检查英文。先列出有编号的问题、依据和最小改法，等我选择后再修改；不要自由润色。若有字数要求，以我本次提供的要求为准。

等助手列出建议后，可以回复“只采用 P1-01”或“全部不采用”。对话中的范围控制依靠助手遵守规则，你仍需核对差异；本地网页工具则会用程序校验其支持的 P1/P2 替换范围。两种方式可选其一。

### 修改后还想再检查意思？

可以另做回译核对（BTI）：只把修改后的英文交给独立翻译工具回译，再与确认的中文对照。也可以对比作者修订后的机翻英文与最初 AI 英文（AEC）。这两项只报告意思差异，不自动改稿；当前页面没有专用 BTI/AEC 按钮。

## 第一步：把工具下载到电脑

仓库就是这个项目在 GitHub 上存放文件的地方。

1. 在仓库页面上方点击 **Code（代码）** 标签。
2. 在文件列表右上方，点击绿色的 **Code** 按钮。
3. 在展开的菜单中点击 **Download ZIP（下载 ZIP）**。
4. 下载完成后，在电脑的“下载”文件夹里找到 ZIP 压缩包。
5. 右键点击压缩包，选择 **全部提取**。
6. 在弹出的窗口中点击 **提取**。
7. 打开提取出来的文件夹。
8. 找到 `start_windows.cmd`。

如果电脑隐藏了文件扩展名，这个文件可能显示为 `start_windows`。它的类型是“Windows 命令脚本”。

**不要在压缩包里面直接启动。** 请先完成“全部提取”。

**完成检查：** `start_windows.cmd` 旁边应当有 `paperchoose`、`scripts`、`examples` 等文件夹。后文把这个位置称为“项目文件夹”。请保留目录结构，否则程序可能无法启动。

## 第二步：准备 Python（只需做一次）

基础工作台支持 Python 3.10 或更新版本。本候选版的可选翻译依赖限定 Python 3.10–3.12，首次安装建议使用 3.12。

不确定是否已安装时，在终端输入 `py --version`；找不到命令再试 `python --version`。已有符合要求的版本就不用重复安装。

如果没有安装，或者不确定：

1. 打开 [Python 官方 Windows 安装管理器下载页](https://www.python.org/downloads/release/pymanager-264/)。
2. 在页面的 **Files → Windows** 区域，点击 **Download Installer (MSIX)**。下载的是安装管理器，后面还要用它安装 Python 3.12。
3. 打开下载的 `.msix` 文件，按安装窗口的提示完成安装。
4. 在 Windows 开始菜单中搜索并打开 **终端**。终端是输入命令的窗口。
5. 在终端中输入下面的命令并按回车。这条命令会安装 Python 3.12。

```text
pymanager install 3.12
```

6. 安装完成后，在终端中输入下面的命令并按回车。

```text
py -3.12 --version
```

**完成检查：** 终端显示 `Python 3.12.x`。其中的 `x` 表示版本末尾的数字，不需要输入字母 `x`。

如果第一条命令提示“找不到命令”，先关闭终端再重新打开。仍然不行时，参考 [Python 官方 Windows 安装说明](https://docs.python.org/3/using/windows.html)。已经使用其他方式装好 Python 的人，不必重复安装。

只使用原有核对与择项修改功能，不需要额外依赖。若要在页面里直接翻译，请再完成下面的安装。

### 安装本地翻译（可选，只需一次）

1. 在解压后的项目文件夹里双击 `setup_local_translation.cmd`。
2. 窗口会说明需要联网下载依赖和中英模型。愿意安装时按 **Y**，不安装按 **N**。安装程序不读取稿件。
3. 等待窗口显示 `Done`。下载量较大，需要数百 MB 以上空间；速度取决于网络。
4. 关闭原来的工具启动窗口，再按第三步重新打开工具。
5. 页面应显示翻译模型已安装，并可以点击两个翻译方向。每次最多处理 5,000 个字符，长稿按章节处理。

若安装失败，保留窗口中的错误信息。原有手动导入译文的功能仍可使用。依赖和模型放在项目里的 `.paperchoose-venv`、`.translation-data` 文件夹中，不需要上传到 GitHub。

已经熟悉命令行的用户，可在项目目录建立虚拟环境后安装 CPU 版 PyTorch、`requirements-translation.txt`，再运行 `python -m paperchoose.translation --download-models`。具体命令见 `docs/LOCAL_TRANSLATION.md`。

## 第三步：打开工具

1. 打开项目文件夹。
2. 双击 **`start_windows.cmd`**。
3. 保持启动时出现的终端窗口打开。
4. 如果浏览器没有自动打开，把下面的地址输入浏览器地址栏并按回车。

```text
http://127.0.0.1:8765/
```

这个地址指向你自己的电脑。只有工具启动后才能打开，发给别人也不会打开你的页面。

**完成检查：** 页面显示“本地工具已就绪”。如果页面无法连接，请查看下文“打不开时，先检查这几件事”。

**不要直接双击项目里的 `index.html`。** 页面需要配合刚才启动的程序才能工作。

## 第四步：不用自己的文章，先试一次

“合成示例”是专门编写的演示文字，不是真实论文。它自带修改建议，不需要先找 AI。

如果页面中已有自己的稿件，请先下载需要保留的结果。载入示例会替换页面中的内容。

1. 点击 **试用合成示例**。页面应显示中文、英文和两条修改建议。
2. 阅读每条建议的“原英文”“建议替换”“中文依据”和理由。
3. 只勾选 **P1-01** 旁边的 **采用此项**。P1-01 是建议编号。
4. 点击 **预览所选修改**。
5. 检查“新英文稿”：`always improves` 应变成 `may improve`，另一处建议涉及的文字应保持原样。
6. 如果结果符合你的选择，点击 **确认并下载结果**。浏览器应下载 `paperchoose-revision.zip`。
7. 点击 **全部不采用**。页面会自动生成新的预览。
8. 检查“修改差异”：页面应显示“无修改”。

**完成检查：** 选中一项时，程序只修改这一项。全部不采用时，新英文稿与输入的英文一致。

## 第五步：处理自己的中英文

### 1. 放入需要核对的文字

先选一小段你已确认原意的中文，以及对应的英文译稿。还没有英文时，先输入中文并使用“中文 → 英文”；查看预览并采用后再继续。

1. 把中文粘贴到 **中文原稿** 框。
2. 把英文粘贴到 **英文译稿** 框。

如果文字在 Word 或 PDF 中，先复制需要核对的段落。当前工具不能直接导入 Word 或 PDF。

如果已有 TXT 纯文本文件，可以点击对应文字框旁的 **导入 TXT**。每份文件不得超过 200,000 字节，约 200KB。文件需要使用 UTF-8 编码。遇到编码错误时，可先用记事本打开文件，再复制文字到页面。

### 2. 把核对请求交给 AI

1. 点击 **导出给助手的核对请求**。浏览器应下载 `paperchoose-audit-request.zip`。
2. 按第一步的方法解压这个 ZIP。

你会看到两个文件：

| 文件 | 是什么 |
|---|---|
| `AUDIT_PROMPT.md` | 告诉 AI 应该怎么检查的说明 |
| `request.json` | 你刚才放入的中英文，以及程序需要的版本信息 |

3. 确认这次中英文材料可以交给你选用的 AI 服务处理。
4. 打开该 AI 助手。
5. 向助手提供上述两个文件，以及项目文件夹中的 **`SKILL.md`**。

`SKILL.md` 是核对规则。若助手还需要规则中引用的文件，请从项目的 `references` 文件夹提供相应文件。

可以复制这句话一起发送：

> 请按照我提供的 SKILL.md 和 AUDIT_PROMPT.md，核对 request.json 中的中英文。只列出有依据的修改建议，不直接改稿、不替我选择。请按要求返回完整的 JSON 修改清单，最好提供可下载的 audit.json 文件。

这里的 **JSON** 就是程序能读懂的清单格式。通常让助手生成即可，你不需要自己写。

### 3. 把建议导回工具

如果助手给了 JSON 文件：

1. 下载助手返回的文件，例如 `audit.json`。
2. 在工具的 **查看核对结果** 区域点击 **选择核对 JSON**。
3. 选择刚下载的文件。

如果助手只返回 JSON 文字：

1. 复制完整的 JSON 内容。不要复制额外解释或代码框边界的三个反引号。
2. 在工具中点击 **粘贴或查看核对 JSON**。
3. 把复制的内容粘贴到展开的文字框中。

完成其中一种导入方式后，点击 **校验并展示修改项**。

**完成检查：** 页面列出修改建议，默认均未选中。若助手没有提出建议，页面会说明清单中没有修改项。这不表示程序已证明英文没有问题。

如果页面报错，把错误提示和原核对请求交给助手修正。不要为了跳过报错，随意更改版本信息。

### 4. 选择、预览、下载

1. 阅读每条建议的中文依据、替换文字和理由。
2. 勾选你同意的建议旁边的 **采用此项**。
3. 点击 **预览所选修改**。
4. 检查“新英文稿”和“修改差异”。
5. 如果结果符合你的选择，点击 **确认并下载结果**。

程序会检查修改位置和稿件版本，但不会替你判断建议是否真的符合原意。不同意的建议可以不选。

如果你中途改了中文或英文原稿，需要为新稿重新生成核对请求，不能继续套用旧稿的修改清单。

## 下载结果后，看哪个文件？

把结果 ZIP 解压，会看到三个文件：

| 文件 | 怎么看 |
|---|---|
| `revised.en.txt` | **这是修改后的英文稿。** 双击打开，可以把需要的文字复制回 Word。 |
| `changes.diff` | 修改前后的对照。想检查改了哪里时，用记事本打开。 |
| `decisions.json` | 这次选择和执行的记录，保存备用即可。 |

目前导出的是纯文字，不会自动带回原 Word 文件的字体、批注和排版。

## 用完怎么关闭？

**关闭或刷新页面会清除未下载的内容。** 请先保存需要保留的结果。

1. 下载需要保留的结果。
2. 回到启动程序时出现的终端窗口。
3. 按 **Ctrl+C** 停止程序。
4. 关闭终端窗口和工具页面。

下次使用时，重新双击 `start_windows.cmd`。

## 打不开时，先检查这几件事

| 遇到的情况 | 可以怎么做 |
|---|---|
| 点了启动文件，没有打开页面 | 查看终端提示。确认已安装 Python，并且是在解压后的项目文件夹里启动。 |
| 浏览器提示无法连接 | 确认启动窗口还开着，再检查地址是不是 `http://127.0.0.1:8765/`。 |
| 提示 `No module named paperchoose` | 检查启动文件旁边是否有 `paperchoose` 文件夹。若 `core.py` 等全散在同一层，说明目录不完整，需要取得保留目录的项目文件。 |
| 提示版本不匹配 | 说明当前文字与生成建议时的文字不同。用当前稿件重新导出请求并核对。 |
| 某条建议不能选择 | 根据页面提示让助手修正定位。不要强行套用。 |
| 两条建议修改同一段，提示冲突 | 先选其中一条，或让助手重新整理建议后再选择。 |

如果仍然打不开，请到仓库顶部的 **Issues（问题）** 页面反馈。写清操作步骤和完整错误提示。若附截图，请避开私人稿件。发布问题通常需要登录 GitHub。

## 文字会上传到哪里？

Paper Choose 本身在你的电脑上处理文字，不自动调用云端 AI，也不覆盖原文件。

首次安装本地翻译需要联网下载软件与模型。安装后的翻译在本机运行；程序不会自动把稿件发给翻译网站。“下载本次翻译记录”会保存当时的中英文和译文，请在本地保管。

如果你另外使用在线翻译软件，文字的数据去向取决于那个服务。当你把核对请求交给外部助手时，请求里包含的中英文会交给那个服务处理。这一步由你自己决定，发送前请确认材料可以交给该服务。
